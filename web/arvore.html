Bem-vindo à documentação de testes da API do GRP

Esta página reúne o que foi aprendido em testes reais dos Web Services do GRP-Minas: como montar cada chamada, o que o GRP aceita, o que ele recusa e por quê. Tudo aqui vem de chamadas reais, com data.

Você não precisa instalar nada. Preencha os seus dados, gere o XML, envie e cole a resposta: a página explica o que aconteceu e leva o número gerado para a próxima etapa.

O que você encontra aqui

O ciclo de execução da despesa

As quatro chamadas são encadeadas: cada etapa usa o número do documento gerado na etapa anterior.

Operações de manutenção

Usadas sobre documentos que já existem, registrados pela API ou pela tela do GRP.

Como usar, em cinco passos

  1. Informe os dados da execução uma vez: sistema, órgão, UO, UA, ordenador, operador e credor. Ficam só no seu navegador.
  2. Preencha a etapa e leia a conferência: em vermelho o que o GRP vai recusar, em amarelo o que vale conferir.
  3. Envie pelo botão da página (com o ajudante de envio) ou copie o comando pronto para PowerShell, curl, Python ou Postman.
  4. Cole a resposta do GRP. A página explica o resultado.
  5. Leve para a próxima etapa com um clique: o número do processo, do empenho ou da OLP é preenchido automaticamente.

Códigos já vistos

Contrato de cada serviço

O contrato (o arquivo WSDL do serviço) é a lista oficial dos campos que cada serviço do GRP aceita: o nome de cada um, o tipo de valor e se é obrigatório. Se o XML trouxer um campo fora dessa lista, ou um número com texto dentro, o GRP recusa antes de olhar qualquer regra (HTTP 500, "Unmarshalling Error").

Campo ou tag? É a mesma coisa vista de dois lados: o campo é a informação (ex.: o valor a pagar); a tag é como ela aparece escrita no XML, entre < > — <valorAPagar>1260.00</valorAPagar>. Os campos vêm em grupos (ex.: "cada item de pagamento"), que são tags que guardam outras tags.

Obrigatório no contrato só quer dizer que a tag tem de existir. O GRP pode exigir outros campos conforme o caso (ex.: a finalidade com conta específica). A aba Montar e testar confere essas exigências, e os casos reais mostram cada uma.

Dicionário de tags

O significado de cada campo, o que o contrato atual diz dele (tipo e obrigatoriedade, por serviço) e como preenchê-lo, com o que já se confirmou em chamadas reais.
